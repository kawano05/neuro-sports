# ひとおし スポーツ（野球・ボッチャ）

スイッチ1つ（ニューロノードなど）で遊ぶ、野球とボッチャのウェブアプリ。
ニューロノード練習アプリ「neuro」とは別のアプリとして、一般社団法人ケアの方舟からの依頼で作った。
ブラウザだけで動き、Zoom などで離れた場所から参加する人も、同じ部屋に入って交代で遊べる。

**公開先: https://kawano05.github.io/neuro-sports/** （main へ push すると、GitHub Actions が出し直す）

## 遊び方

- **押す** … スペース・Enter・ニューロノード（キーボードのスイッチ）・画面の大きな「おす」・遊びの画面のクリックやタップ、どれでも同じ1回。
  ニューロノードは機器によって送るキーが違う（F5・F12 など）ので、遊びの画面ではどのキーでも1回の押しにしている（修飾キー・Tab・Esc を除く）。
- **部屋を つくる** … ホストになる。6けたの番号とリンクが出る。
- **部屋に はいる** … リンクか番号で入る。「あそぶ」か「見るだけ」を選ぶ。番号だけのときは、ホストの許可を待つ。
- **ひとりで あそぶ** … インターネットを使わず、この端末だけで遊ぶ。
- 待っている部屋でスイッチを押すと、自分の名前が全員の画面で弾む（スイッチの ためし）。
- 遊んでいるあいだ、番でない人が押すと「おうえん」になる（名前が弾む）。

### 野球

本塁の上で円盤（回転台）が回っている。ふちのボールが黄色い帯（あたる ところ）に来たときに押すと、
三塁側のバットが横に振れて打てる。押したタイミングで打つ向きと強さが決まり、ボールは飛んで、落ちて、はねて、盤の上を転がる。
結果は、ボールが止まった場所で決まる。

- 外野のフェンスは区画に分かれていて、ヒットの区画のあいだにアウトの区画がある
  （センターがホームラン、外へ スリーベース・アウト・ツーベース・アウト・ヒット）。フェンスはセンターが遠く、線ぞいが近い。
- 盤の上の穴は、野手のいる位置の7つ（一塁・二塁・遊撃・三塁・左・中・右）。ゆっくり転がってきたボールは落ちて、アウト。
  飛んでいる間（はねている間も）は穴に落ちない（内野の穴を飛びこえる）。
- どこにも入らずに止まったら、内野ならアウト（ゴロ）、外野ならヒット（野手のあいだに落ちた）。
  アウトになるのは、見える所（守備の穴・フェンスのアウトの区画・内野）だけ。
- 落ちる前にホームランの区画に届いたら、フェンスをこえてスタンドに入る。
- 帯の真ん中（オレンジ）で打つほど、まっすぐ強く、高く飛ぶ。早く振ると左へ、遅く振ると右へ。
  強さは、その向きのフェンスまでの道のりに合わせてあり、端の当たりでも線ぞいのヒットの区画に届く。
  向きと強さには、本物の盤のようなばらつきがある（ねらい通りにはいかない）。

当たった瞬間に、ほんの少し止めて（0.07 秒）カメラを少し寄せる。ボールが飛ぶと、影は地面に残り、
ボールは上がって大きく見える。飛んだ道すじは白い線で残る。落ちると「トン」と鳴る。
カメラは盤全体へ引いて、ボールを追う。止まったら結果を出し、次のボールの前にまた寄る。
空振り・見送りは数えない（ストライクは無い）。円盤が回っているので、ボールはまた来る。

支援者の設定「試合の 形」（どれも必ず終わる）:
- **打席制（既定）** … 赤・青が1人ずつ交互に打つ。1人が決めた数（既定 2）だけ打ったら おわり。
  点は ヒット1・ツーベース2・スリーベース3・ホームラン4（ランナーは無い）。アウトは0点。名前の横の丸で残りの打席が見える。
- **イニング制** … 3アウトで攻守交代、決めた回まで。ランナーあり。1回の攻撃は打者一巡（3人より少なければ3打席）で打ち切る。
- **みんなで（アウトなし）** … アウトの場所に止まってもヒットにする。打った人はランナーになり、本塁に帰ると「みんなの得点」。

ばらつきのある盤で、押すタイミングのずれごとに試し計算すると（当たる広さ「ひろい」）:

| 押すずれ | アウト | ホームラン | 3アウトまで（打者一巡で打ち切る前） |
| --- | --- | --- | --- |
| ±80ms（上手） | 約16% | 約3割 | 約19打席 |
| ±200ms | 約24% | 約2割 | 約12打席 |
| でたらめ | 約29% | 約1割 | 約10打席 |

帯のうすい色で打っても、アウトは約3割（外野で止まった球をヒットにする前は約5割）。
線ぞいのヒットの区画は、ねらって打てば約3割（以前は約1割）。

> 仕組み（本塁の回転台にボールを乗せ、スイッチでバットを振り、止まった場所で結果が決まる野球盤）は、
> ユニバーサル野球（堀江車輌電装株式会社。「ユニバーサル野球」は同社の登録商標。特許第6729956号）を参考にした。
> このアプリでは名前・ロゴ・盤の絵や色・穴の並びは使っておらず、画面・盤の作りは独自のもの。

### ボッチャ

参考資料（ケアの方舟の「プロトタイプ３版」: 回転台に乗せたランプを、スイッチで「向きを変える」「ボールを放す」）を画面に移した。

1. **むき** … ランプが左右に首を振る。押すと止まる。回転台のふちの目盛りで向きが分かる。
2. **つよさ** … 玉がランプを上り下りする。高い段（濃いオレンジ）で放すほど遠くへ転がる。

支援者の設定で「1回（むきだけ）」にすると、強さはジャックまで届く強さに決まる。
赤・青のチームに分かれ、本物と同じく、ジャックから遠いチームが次に投げる。玉どうしはぶつかって、はじかれる。
遊ぶ人が1人（1チーム）のときは、点ではなく「いちばん近い玉」を見せる。

## 支援者の設定（⚙、ホストのみ。全員に同じに効く）

| 遊び | 設定 | 選べるもの |
| --- | --- | --- |
| 野球 | 円盤の はやさ | いちばん ゆっくり（1周 12秒）/ とても ゆっくり（8秒）/ ゆっくり（6秒）/ ふつう（4.6秒）/ はやい（3.4秒） |
| 野球 | 当たる 広さ | せまい（±0.22秒）/ ふつう（±0.38秒）/ ひろい（±0.6秒）/ いつでも |
| 野球 | 試合の 形 | 打席制（1人 ◯打席）/ イニング制（3アウト）/ みんなで（アウトなし） |
| 野球 | 何回まで（イニング制） | 1回 / 2回 / 3回 |
| 野球 | ひとり 何打席（打席制・みんなで） | 1 / 2 / 3 / 5 / ずっと |
| 野球 | 交代 | 打ったら つぎの人 / 支援者が きめる |
| ボッチャ | 目盛りの はやさ | ゆっくり / ふつう / はやい（1往復 6.4 / 4.6 / 3.3秒） |
| ボッチャ | 押す 回数 | 1回（むきだけ）/ 2回（むき → つよさ） |
| ボッチャ | 1チームの 玉 | 1 / 2 / 3 / 6 |
| ボッチャ | とどく ところの 線 | あり / なし |
| 両方 | 合図の 音 | あり / なし |

読み上げ（あり / なし）と音の大きさ（小さめ / ふつう / 大きめ）は、端末ごとに選ぶ。

### 合図の音

neuro で測って決めた大きさをそのまま使う（`neuro/src/lib/audio.js` の `CUE_TONE_GAIN` 0.4、前ぶれは約9dB小さい純音）。
押す瞬間の音は、2026-10-21 の打ち合わせを受けた「パキッとした」高い音（倍音つき 880Hz）。

- 野球: ボールが帯の真ん中に来る瞬間に「ポーン」、その前に2つ「ピッ」（ピッ・ピッ・ポーン）。
- ボッチャ: ランプがジャックのほうを向いた瞬間と、ジャックまで届く高さに玉が来た瞬間に「ポーン」。

## 判定の時刻

- 押した時刻は、入力の入口の最初の1行で取る（`performance.now()`）。描画のコマに頼らない（neuro と同じ）。
- 同じ1回の操作から出る重なり（pointerdown と click など）は 150ms のあいだ1回にまとめる。押しっぱなしの連続キーは数えない。
- ゲストは、ホストとの時計のずれを測って（行って帰る時間がいちばん短い回から）、押した時刻を **ホストの時計** に直して送る。
  ホストはその時刻で判定するので、ゲストが自分の画面で見ていたとおりに当たる（通信の遅れで、判定がずれない）。

## 入る決まり（知らない人が入れない・なりすませないように）

- 部屋の番号は6けた。番号は総当たりで見つけられるので、**番号だけで来た人は、ホストが「入れる」を押すまで待つ**。
  待っているあいだ、部屋の様子（名前・状態）は何も送らない。
- ホストの「リンクを コピー」で配るリンクには、推測できない合言葉（key）が付く。リンクから来た人はそのまま入れる。
- 人の id はホストが決める。入り直しには、ホストが本人にだけ渡す秘密の札（token。このタブにだけ覚える）を使う。
  id は全員に見えるので、id では入り直せない（なりすましを防ぐ）。
- ホストは人を外せる（×を2回）。外した人の札は使えなくなり、リンクの合言葉も作りなおす（前のリンクでは許可が要る）。
- あそぶ人は8人まで、部屋は20人まで（部屋の画面に「あそぶ 2 / 8人　部屋 3 / 20人」）。
- **合言葉と札は、線の上に流さない**（`src/lib/handshake.js`）。ホストが案内役のサーバーから一瞬切れたすきに、
  だれかが同じ番号を名乗っても（にせのホスト）、合言葉も札も盗めない。
  1. ゲストは乱数と、札の目じるし（札からは戻せない）だけを送る。
  2. ホストは、合言葉（と札）を知っている「その場かぎりの印」（HMAC-SHA256）を返す。
  3. ゲストは印を確かめてから、自分も印を返す。確かめられなければ、名前だけを送って許可を待つ。
  - 印には、2人の乱数と、この線の暗号のかぎの指紋（DTLS の fingerprint）を混ぜる。にせのホストが本物へ
    別の線を張って印を横流ししても、指紋が合わないので通らない。
  - あいさつを10秒で終えない線は切る。あいさつの前に届く「入れた」は受けない。
  - 番号だけで来た人は、もともと秘密を持たないので、ホストが本物かは確かめられない（名前だけが渡る）。

## つなぎ方（サーバーなし）

GitHub Pages は静的なサイトで、サーバーを置けない。

- 相手を見つける（シグナリング）だけ、[PeerJS](https://peerjs.com/) の公開サーバー（0.peerjs.com）を使う。部屋の番号はここに届く。
- ゲームの状態と「だれが押したか」は、ブラウザどうしで直接（WebRTC のデータチャネル、暗号化）流れる。名前もこちらを通る。
- 直接つながらないネットワークでは、PeerJS の中継（TURN）を通る。
- ホストだけがゲームを進め（`src/lib/engine.js`）、変わるたびに全員へ状態を配る。ゲストは押した時刻を送るだけ。
- インターネットにつながらないときは、「ひとりで あそぶ」と同じ動きになる。

**ホストの端末は、部屋を作ったタブを前に出したままにする。** iPad で別のアプリへ切り替えると、部屋が止まる。

## 開発

```powershell
npm install
npm run dev      # http://localhost:5190
npm test         # 決まり（純粋関数）と、入るときのあいさつのテスト
npm run build    # dist/ に書き出す
```

- `src/lib/games/baseball.js`・`boccia.js` … 判定・ランナー・転がり・点数（画面にも通信にも依存しない）
- `src/lib/engine.js` … 部屋の状態を進める（ホストだけ）
- `src/lib/session.js`・`net.js` … ホスト / ゲスト / ひとり、PeerJS、時計合わせ
- `src/lib/handshake.js` … 入るときのあいさつ（ホストが本物かを確かめる印）
- `src/lib/input.js` … スイッチ1つの受け口
- `src/lib/audio.js` … 合図の音・効果音・読み上げ

デザインについて: 「ユニバーサル野球」の名前・ロゴ・絵・見た目は使っていない。仕組み（回る円盤とスイッチで打つ）だけを参考にした独自のデザイン。
